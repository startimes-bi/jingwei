# 银河 CEO 门户大区原始数据

## 范围

这是独立于节目包原始数据的 pipeline。正式表格为 `银河CEO门户大区原始数据 YYYY-MM-DD HH:MM`，token 与节目包表不同；每日程序只更新本表的第一个 Sheet，不改节目包表。

## 数据粒度

主 Sheet 的唯一键为：

```text
(load_date, business, company_id, region_id)
```

`region_id` 为空表示数据库明确提供的公司总计行；非空表示数据库明确提供的大区行。程序直接写入数据库行，不把城市或大区行相加生成公司总计，也不把公司总计与大区明细再次相加。

充值金额的上游数据存在一种已复核的零值占位：同一日期、业务、公司/大区键出现两条记录，一条为 0、一条为非 0，且对应节目包明细之和与非 0 值相等（允许 0.01 USD 舍入差）。程序只在这一条件全部满足时保留非 0 值；其他冲突仍然阻断更新。

新增用户只在 v2 公司总计为 0、旧版同口径公司总计与大区明细合计完全一致时采用旧版公司总计；其他新增用户差异仍然阻断更新。

主 Sheet 列顺序固定为：日期、业务类型、国家/公司、公司 ID、大区 ID、新增用户、充值人数、充值收入（USD，税前）、扣费人数、扣费收入（USD，税后）、更新时间（北京时间，UTC+8）。

第二个 Sheet `公司和大区对应表` 保存公司与大区名称；第三个 Sheet `汇率税率` 保存按整月生效的汇率和税率。两个参考 Sheet 不由每日原始数据更新器改写。

## 日期窗口与日更

程序入口为 `src/galaxy_ceo_portal_region_daily_update.py`。每次先读取飞书当前数据范围，再查询数据库五张指标表的共同最新日期。只有共同最新日期达到北京时间昨日才写入。

窗口为最近 400 个自然日：结束日为 `min(数据库共同最新日，北京时间昨日)`，起始日为结束日往前推 399 天。例如共同最新日为 `2026-09-13` 时，窗口为 `2025-08-10` 至 `2026-09-13`。每次会补齐窗口内缺少的业务日期，并删除窗口起始日前的数据。

调度模板为：

- `deploy/systemd/galaxy-ceo-portal-region-update.timer`：北京时间每天 15:55；
- 若数据还没有昨日，按小时在 16:55、17:55、18:55 再试，最多额外 3 次；
- 节目包 pipeline 仍在 16:00 使用自己的 service、timer、配置项和窗口策略。

本机已将大区 pipeline 的 service/timer 安装到用户级 systemd 并启用；迁移到其他环境时，需重新安装模板、执行 `systemctl --user daemon-reload`，再启用 `galaxy-ceo-portal-region-update.timer`。节目包 timer 的当前状态和交付记录见 [`docs/operations/galaxy_ceo_portal.md`](../operations/galaxy_ceo_portal.md)。

## 安全与验收

数据库连接使用只读事务和固定字段查询；凭据只从受控 `.env` 读取，不进入代码或 Git。`--dry-run` 只读取数据库和飞书并输出待追加/删除数量，不写入任何一方。正式日更结束后向 `FEISHU_REPORTING_CHAT_NAME` 配置的飞书群发送结果卡片；通知失败不会改变数据任务的返回码。

程序会验证公司总计行与大区行的粒度关系；金额允许分币级舍入差异，但不会用求和结果替换数据库原始行。日更写入前会检查窗口日期不缺失、无窗口外日期和业务键不重复；成功更新后会回读表头、日期覆盖、业务键集合、行数和标题，只更新大区表名称的北京时间分钟后缀。
