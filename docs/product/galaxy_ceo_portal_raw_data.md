# 银河 CEO 门户原始数据

## 目标

从 MGW 数据库读取最近 400 个自然日的 DTT、DTH 指标，按公司和节目包整理为飞书电子表格。数据库只读，程序不执行任何数据库写操作。

## 输出表结构

正式电子表格名称：`银河CEO门户原始数据 YYYY-MM-DD HH:MM`；表格 token 不变，名称后缀为最近一次写入/维护时间。

首个 Sheet 的列顺序固定为：

| 顺序 | 列名 | 规则 |
| ---: | --- | --- |
| 1 | 日期 | MGW 的 `load_date`，作为无时区业务日期，以飞书日期序列值写入并显示为 `YYYY-MM-DD` |
| 2 | 业务类型 | 只保留 `DTT`、`DTH` |
| 3 | 公司 ID | MGW 的 `company_id` |
| 4 | 节目包 | MGW 的 `package_class`；NULL 总计行写成 `公司合计（package_class=NULL）` |
| 5 | 新增用户 | `metric_sub_new_count_v2.sub_day_new_count` |
| 6 | 充值人数 | `metric_sub_recharge_count.sub_recharge_count` |
| 7 | 充值收入（USD，税前） | `metric_sub_recharge_money.recharge_money` |
| 8 | 扣费人数 | `metric_sub_deduction_count.sub_deduction_count` |
| 9 | 扣费收入（USD，税后） | `metric_sub_deduction_money.deduction_money` |
| 10 | 更新时间（北京时间，UTC+8） | 本次写入批次的北京时间，精确到分钟；以飞书原生日期时间数值写入 |

另外保留两个参考 Sheet：

- `公司对应表`：按当前 MCP 公司维度原样写入公司 ID、英文名称、中文名称，不按主数据日期筛选。
- `汇率税率`：按当前 MCP 返回的汇率和税率写入，但只保留覆盖原始数据业务日期范围的月份；生效月份为整月文本 `YYYY-MM`，不能伪装成某一天。

## 数据粒度与聚合规则

目标唯一键为：

```text
(load_date, business, company_id, package_class)
```

“公司维度聚合”不是把城市和大区加起来。每张指标表只取公司级基准记录：

```text
region_id IS NULL
AND sale_area_id IS NULL
```

同时排除指标自己的下钻拆分行：

- 新增用户：`fta_flag`、`wct_flag`、`tv_class` 均为空。
- 充值人数：`fta_flag`、`wct_flag`、`rate_flag`、`active_label` 均为空。
- 充值收入：`wct_flag`、`rate_flag`、`tv_class`、`active_label` 均为空，且 `load_month = LEFT(load_date, 6)`。
- 扣费人数：`fta_flag`、`wct_flag`、`rate_flag`、`active_label` 均为空。
- 扣费收入：`fta_flag`、`wct_flag`、`rate_flag`、`tv_class`、`active_label` 均为空，且 `load_month = LEFT(load_date, 6)`。

这些拆分字段为空的记录是公司级基准值，不能再与 active_label、资费周期、FTA/WCT 或地区记录相加。若同一目标键仍出现多条记录，程序只允许它们的指标值完全相同并去重；值不一致时直接失败，禁止猜测或求和。

已在 2025-11-10 的源数据中发现一种可复核的上游占位情况：充值金额的公司总计行恰有两条记录，一条为 0，另一条非 0；五个异常公司的非 0 值分别与对应节目包明细之和相等（允许 0.01 USD 的金额舍入差）。程序只对这一种“充值金额 + 公司总计 + 两条记录 + 0/非 0 + 明细复核通过”的情况丢弃 0 占位行；任何其他冲突仍然阻断同步。

`package_class IS NULL` 在当前数据中是公司/全部节目包的总计行，不是普通的“未分类”节目包。它可以保留用于核对，但不能和具体节目包明细一起再次求和。若后续需要严格的节目包明细，应将这些总计行单独放入汇总视图。

某项指标没有对应源记录时写空单元格；源记录存在且值为 0 时写数字 0。这样不会把“没有记录”伪装成“确认为零”。

## 日期、汇率与时区

- 最新日期取五张指标表中 DTT/DTH 数据的共同最大 `load_date`，避免某一张表尚未更新时混入不完整日期。
- 最近 400 天按自然日计算，包含起止日：`latest_date - 399 days` 至 `latest_date`。
- `load_date` 是业务数据日期；不能当作本次写入时间。
- 写入时间由程序在一个批次开始时生成，使用 `Asia/Shanghai`，秒和微秒归零；表头明确标注 `北京时间，UTC+8`。
- 充值和扣费金额在源指标定义中已经是 USD；程序不重复换算。

## MCP 核对结果

2026-09-13 对乌干达公司 ID 7、业务日期 2026-09-11 做了数据库与 MCP 的公司级核对。人数和新增用户完全一致：

| 业务类型 | 新增用户 | 充值人数 | 扣费人数 |
| --- | ---: | ---: | ---: |
| DTT | 272 | 25,528 | 275,134 |
| DTH | 538 | 22,193 | 325,085 |

金额存在分币级舍入差异：充值收入最大差异 0.02 USD，扣费收入最大差异 0.03 USD。写入值以数据库公司级基准行作为来源；MCP 用于语义和数值校验，在核对流程中金额差异绝对值不超过 0.03 USD 视为舍入差异，超过则阻断同步并报告。

2026-09-13 又对 37 个公司/国家 ID 各抽取 3 个随机业务日（2025-09-26、2025-11-14、2026-06-23），逐项核对 DTT/DTH 的五项指标。MCP 有数值的记录中，新增用户 148 条、充值人数 113 条、充值金额 147 条、扣费人数 136 条、扣费金额 136 条；其中分别有 2、6、9、2、7 条与数据库公司基准行不一致。进一步按大区/城市展开确认，MCP 的公司分组值等于下钻城市行之和，且部分样本没有 `region_id` 与 `sale_area_id` 为空的公司基准行。因此 MCP 的公司分组不能直接作为本表的数值验收口径；除非 MCP 提供明确的公司基准记录，否则只用于维度、业务类型和数量级抽检。本表继续以数据库公司级基准行作为写入来源，不把城市或大区相加。

## 写入策略

- 飞书 App ID、App Secret 和数据库密码只从受控配置路径读取，不进入代码、命令输出、Git 或审核提示词。
- 数据库查询只允许固定的五张指标表和固定列，不使用 `SELECT *`。
- 先建立空的正式表和表头，再分批写入主 Sheet；默认批量大小为 500 行。
- 数据库按默认 30 个自然日分块查询（可用 `--query-chunk-days` 调整），避免大范围聚合查询超时。
- 每次日更结束后向 `FEISHU_REPORTING_CHAT_NAME` 配置的飞书群发送一张结果卡片；卡片包含产出表格链接、表格状态、数据窗口、执行动作和质检摘要。通知发送失败只记录日志，不改变数据任务的成败。
- `--dry-run` 只执行查询和校验，不写飞书。
- `--normalize-date-column` 只把已有主 Sheet 的 A 列日期文本转换为飞书日期值，不重新加载其他数据。
- `--sync-reference-sheets --reference-json PATH` 只更新两个空的参考 Sheet；MCP 结果先整理为 JSON，通过受控入口传入，程序不会自行猜测或补齐名称、汇率、税率。
- `--rename-spreadsheet-with-time` 使用北京时间生成 `YYYY-MM-DD HH:MM` 后缀；后续按固定名称前缀校验，因此不影响同一 token 的增量维护。

## 每日增量更新

每日更新程序为 `src/galaxy_ceo_portal_daily_update.py`，设计为北京时间每天 16:00 触发：

1. 先读取正式主 Sheet 的当前最大业务日期和已有业务键。
2. 查询五张指标表的共同最新日期；只有共同日期达到北京时间“昨日”才开始写入。
3. 如果未达到昨日，等待 1 小时后重试，最多额外重试 3 次（16:00、17:00、18:00、19:00 四个尝试点）。
4. 对 400 天窗口内缺失的业务日期查询数据库；最新目标日每次复核，用完整业务键去重，补写缺失行。
5. 删除窗口起始日前的旧行，再把窗口维持在最近 400 个自然日；数据库仍为只读连接。
6. 写入前检查目标窗口日期覆盖和数据库业务键唯一性；成功写入后再次回读表头、日期覆盖、业务键集合、行数和标题。
7. 成功后更新电子表格名称的北京时间后缀；表格 token 不变，并向 Reporting 群发送卡片。

服务调度模板位于 `deploy/systemd/`。本机已将节目包 pipeline 的 service/timer 安装到用户级 systemd 并启用；迁移到其他环境时，仍需将对应模板复制到 `~/.config/systemd/user/`，执行 `systemctl --user daemon-reload`，再启用 `galaxy-ceo-portal-update.timer`。大区 pipeline 的独立规则和调度见 [`galaxy_ceo_portal_region_data.md`](galaxy_ceo_portal_region_data.md)。
- 初次装载要求目标 Sheet 为空；程序发现已有数据时应停止，避免重复追加。清理旧数据必须由人工明确执行。

## 验收标准

1. 400 天范围和共同最大业务日期可在运行输出中确认。
2. 目标行只来自公司级基准记录，不含地区或下钻拆分行的累加。
3. 同一目标键没有未解释的不同来源值；只有已通过节目包明细复核的充值金额零占位例外，其余冲突会失败。
4. 充值/扣费列顺序均为“人数在前、金额在后”。
5. 金额单位为 USD，缺失值为空，零值保留为 0。
6. 更新时间显示为北京时间，并且不会因时区转换改变日期。
7. 目标数据窗口日期不缺失；同一日期允许有不同业务/公司/节目包行，但完整业务键不得重复。
8. 写入后通过飞书接口核对表头、日期覆盖、业务键集合、行数和标题。
